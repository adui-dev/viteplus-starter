# ADR-0001：仅使用 Vite+ 官方基础项目模板

- 状态：Accepted
- 日期：2026-10-26
- 关联：FR-001、FR-002、FR-008

## 背景

项目需要同时支持 Vue、React、Application 和 Monorepo，并能长期跟随 Vite+ 默认工具链。

## 候选方案

1. 各框架分别使用 create-vue / create-vite。
2. 从固定模板目录复制完整工程。
3. 统一委托 Vite+ 内置 `vite:application` 与 `vite:monorepo`。

## 决策

采用方案 3。Vue 与 React 都从 Vite+ 的 `vite:application` 入口生成，按语言传入官方 create-vite 的 `vue` / `vue-ts` / `react` / `react-ts` 模板选项（TypeScript 默认）；本项目仅增加校验与可选集成。不得通过 `vp migrate` 替代此路径。

## 理由与权衡

优势：减少官方工程结构重复维护、统一 Vite+ 工具链。代价：依赖官方 CLI 交互及兼容变化，自动化模板参数已结合 Vite+ 官方源码确认，实际生成仍需冒烟验证。

## 额外约束

用户明确要求不增加任何 CI/CD。架构中只提供手动本地检查和测试。

## 2026-10-27：Monorepo 子应用

继续采用官方入口：根用 `vite:monorepo`，成员以根为 cwd 调用 `vite:application --directory apps/<name>`，不再传入只适用于独立工程的 Git 初始化选项。保留官方默认应用和库，不复制独立工程到工作区，也不走迁移流程。选择逐应用 `--workspace` 命令，先保证混合框架与语言的隔离；批量配置另行设计。

实测发现插件包遗漏 Vite peer 会在 pnpm 混合工作区解析到另一类型实例，造成 Vue TS 的 TS2321。采用 pnpm packageExtensions 增量补充已知包的 peer 元数据，保留各应用原有 TypeScript/Node 类型版本；不通过强制统一依赖版本、类型断言或关闭检查绕过。已有扩展冲突时在生成前拒绝修改。

## 2026-10-27：批量生成的执行方式

批量 JSON 只编排官方新建流程，不引入另一套模板。根直接委托 vite:monorepo，成员阶段通过 Node argv 子进程复用既有单应用 CLI，避免重复实现插件合并与路径保护；代价是每个成员启动独立进程。首版限定新工作区并串行执行，失败保留现场，后续再独立设计显式恢复或向已有工作区批量添加的协议。

## 2026-10-27：大屏交付方式

保留参考 AdScreen 的分层意图，重新实现框架无关布局/控制器及 Vue、React 适配。选择向官方应用复制受保护的源码快照，避免依赖尚未发布的 @adui/screen npm 包；代价是后续升级需显式对比迁移，首期拒绝覆盖，不提供自动同步。引擎不使用 CSS 变换，HUD 与两类浮层分离；业务 top/right 常量改为可配置设计单位内缩。不会绕过官方模板，也不会将网格占位宣称为真实 3D 集成。

## 2026-10-27：真实引擎首期

Three.js 先提供独立验收工具和框架无关生命周期运行时，沿用已有 AdScreen 源码接口；不直接扩充新建/批量引擎矩阵，先验证 WebGL、DPR、拾取与清理。选择固定版本依赖、应用内安装与受保护源码快照，保留官方入口；代价是暂需两步启用，现有其他 Three 版本需人工兼容评估。正式引擎选择和按需分块在后续阶段设计，模型授权/解密仍保持独立边界。

## 2026-10-27：引擎选择与加载边界

--engine three 只编排已验证的官方应用增强；JSON 逐应用选择，不给根安装引擎。保留独立首页及已有文件保护，新增/批量与补装共用实现。使用动态 import 的自然模块边界延后引擎请求，不向未知 Vite 配置注入全局分块规则。代价是首次点击仍需等待引擎下载/编译，且引擎单块仍超过默认提醒阈值；允许后续在真实业务负载下专项优化，不调高阈值隐藏问题。

## 2026-10-28：GLB 数据与资源所有权

首期采用用户本地选择、自包含 GLB、浏览器 ArrayBuffer 解析，避免给生成器引入业务模型路径和外部资源加载策略。官方 GLTFLoader 动态导入，解析、请求生命周期、渲染适配与未来模型安全层分离；代价是仅支持已验证的无额外解码器内嵌资源模型。仅清理本查看器独占且已返回的模型资产，环境资源在查看器级复用。格式预检不替代授权或加密认证。

## 2026-10-28：.adui v1 与授权边界

按用户要求采用 .adui 后缀；以 Web Crypto AES-256-GCM 固定版本容器认证元数据与密文，不自行实现密码算法，不把密钥嵌入容器/模板。授权回调与引擎分离，生产鉴权交由业务服务；本地文件 provider 仅用于验收。默认提供能力仍允许明文 GLB 路径，业务控制是否启用。格式与不支持范围见 [MODEL_SECURITY](../MODEL_SECURITY.md)。

## 2026-10-28：无服务端自动模型构建

用户明确将目标调整为提高直接复用门槛，默认采用 embedded env 自动解密，保留 external 模式；参考既有业务的扫描/加载方式，继续使用随机 IV 的 GCM，不复制生产密钥或固定 IV CBC。随机掩码拆分及 hostname 约束不等同加密访问控制。插件以受保护源码目录为输入，禁止 public 原模型复制，保留官方首页及 Vite 其他配置。详见 [MODEL_BUILD](../MODEL_BUILD.md)。

## 2026-10-28：Three 默认模型保护与 KEY/IV 生命周期

依 FR-007 和用户确认的无服务端复用门槛目标，Three 创建默认 embedded，提供 external/none；非引擎及工作区根不统一引入。用户要求 package.json 自动生成 KEY/IV 脚本，采用 KEY 生成及备份轮换命令，IV 在每个 GCM 文件加密时随机生成，不采用全局固定 IV。每应用独立 KEY，dry-run 不生成；只备份并增量修改配置，不覆盖生产密钥。

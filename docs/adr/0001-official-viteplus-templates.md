# ADR-0001：仅使用 Vite+ 官方基础项目模板

- 状态：Accepted
- 日期：2026-10-26
- 关联：FR-001、FR-002、FR-008

## 背景

项目需要同时支持 Vue、React、Application 和 Monorepo，并能长期跟随 Vite+ 默认工具链。

## 候选方案

1. 各框架分别使用 create-vue / create-vite。
2. 从固定模板目录复制完整工程。
3. 统一委托 Vite+ 内置 `vite:application` 与 `vite:monorepo`。

## 决策

采用方案 3。Vue 与 React 都从 Vite+ 的 `vite:application` 入口生成，按语言传入官方 create-vite 的 `vue` / `vue-ts` / `react` / `react-ts` 模板选项（TypeScript 默认）；本项目仅增加校验与可选集成。不得通过 `vp migrate` 替代此路径。

## 理由与权衡

优势：减少官方工程结构重复维护、统一 Vite+ 工具链。代价：依赖官方 CLI 交互及兼容变化，自动化模板参数已结合 Vite+ 官方源码确认，实际生成仍需冒烟验证。

## 额外约束

用户明确要求不增加任何 CI/CD。架构中只提供手动本地检查和测试。

## 2026-10-27：Monorepo 子应用

继续采用官方入口：根用 `vite:monorepo`，成员以根为 cwd 调用 `vite:application --directory apps/<name>`，不再传入只适用于独立工程的 Git 初始化选项。保留官方默认应用和库，不复制独立工程到工作区，也不走迁移流程。选择逐应用 `--workspace` 命令，先保证混合框架与语言的隔离；批量配置另行设计。

实测发现插件包遗漏 Vite peer 会在 pnpm 混合工作区解析到另一类型实例，造成 Vue TS 的 TS2321。采用 pnpm packageExtensions 增量补充已知包的 peer 元数据，保留各应用原有 TypeScript/Node 类型版本；不通过强制统一依赖版本、类型断言或关闭检查绕过。已有扩展冲突时在生成前拒绝修改。

## 2026-10-27：批量生成的执行方式

批量 JSON 只编排官方新建流程，不引入另一套模板。根直接委托 vite:monorepo，成员阶段通过 Node argv 子进程复用既有单应用 CLI，避免重复实现插件合并与路径保护；代价是每个成员启动独立进程。首版限定新工作区并串行执行，失败保留现场，后续再独立设计显式恢复或向已有工作区批量添加的协议。

## 2026-10-27：大屏交付方式

保留参考 AdScreen 的分层意图，重新实现框架无关布局/控制器及 Vue、React 适配。选择向官方应用复制受保护的源码快照，避免依赖尚未发布的 @adui/screen npm 包；代价是后续升级需显式对比迁移，首期拒绝覆盖，不提供自动同步。引擎不使用 CSS 变换，HUD 与两类浮层分离；业务 top/right 常量改为可配置设计单位内缩。不会绕过官方模板，也不会将网格占位宣称为真实 3D 集成。

## 2026-10-27：真实引擎首期

Three.js 先提供独立验收工具和框架无关生命周期运行时，沿用已有 AdScreen 源码接口；不直接扩充新建/批量引擎矩阵，先验证 WebGL、DPR、拾取与清理。选择固定版本依赖、应用内安装与受保护源码快照，保留官方入口；代价是暂需两步启用，现有其他 Three 版本需人工兼容评估。正式引擎选择和按需分块在后续阶段设计，模型授权/解密仍保持独立边界。

## 2026-10-27：引擎选择与加载边界

--engine three 只编排已验证的官方应用增强；JSON 逐应用选择，不给根安装引擎。保留独立首页及已有文件保护，新增/批量与补装共用实现。使用动态 import 的自然模块边界延后引擎请求，不向未知 Vite 配置注入全局分块规则。代价是首次点击仍需等待引擎下载/编译，且引擎单块仍超过默认提醒阈值；允许后续在真实业务负载下专项优化，不调高阈值隐藏问题。

## 2026-10-28：GLB 数据与资源所有权

首期采用用户本地选择、自包含 GLB、浏览器 ArrayBuffer 解析，避免给生成器引入业务模型路径和外部资源加载策略。官方 GLTFLoader 动态导入，解析、请求生命周期、渲染适配与未来模型安全层分离；代价是仅支持已验证的无额外解码器内嵌资源模型。仅清理本查看器独占且已返回的模型资产，环境资源在查看器级复用。格式预检不替代授权或加密认证。

## 2026-10-28：.adui v1 与授权边界

按用户要求采用 .adui 后缀；以 Web Crypto AES-256-GCM 固定版本容器认证元数据与密文，不自行实现密码算法，不把密钥嵌入容器/模板。授权回调与引擎分离，生产鉴权交由业务服务；本地文件 provider 仅用于验收。默认提供能力仍允许明文 GLB 路径，业务控制是否启用。格式与不支持范围见 [MODEL_SECURITY](../MODEL_SECURITY.md)。

## 2026-10-28：无服务端自动模型构建

用户明确将目标调整为提高直接复用门槛，默认采用 embedded env 自动解密，保留 external 模式；参考既有业务的扫描/加载方式，继续使用随机 IV 的 GCM，不复制生产密钥或固定 IV CBC。随机掩码拆分及 hostname 约束不等同加密访问控制。插件以受保护源码目录为输入，禁止 public 原模型复制，保留官方首页及 Vite 其他配置。详见 [MODEL_BUILD](../MODEL_BUILD.md)。

## 2026-10-28：Three 默认模型保护与 KEY/IV 生命周期

依 FR-007 和用户确认的无服务端复用门槛目标，Three 创建默认 embedded，提供 external/none；非引擎及工作区根不统一引入。用户要求 package.json 自动生成 KEY/IV 脚本，采用 KEY 生成及备份轮换命令，IV 在每个 GCM 文件加密时随机生成，不采用全局固定 IV。每应用独立 KEY，dry-run 不生成；只备份并增量修改配置，不覆盖生产密钥。

## 2026-10-28：回归生成器主线

用户明确指出查看器旋转缩放等体验不是本项目主线。验收页只用于证明集成正确，优先需求核对、组合验证与输出保护，再扩展 Cesium/Babylon 生成预设。文件保护统一检查祖先路径并在依赖安装后复核快照，格式化只触及本次输出。计划矩阵、真实构建、浏览器渲染分别记录，禁止混称全部实现完成。

Ant Design Vue 补验遇到 pnpm 12 拒绝 core-js 未审查脚本。核对当前 3.51.0 postinstall 仅输出支持信息，选择精确的 allowBuilds/core-js: false，保留已有用户决策，拒绝复杂配置自动合并；不通过全局放行或关闭严格检查解决兼容性问题。

## 2026-10-28：Cesium 本地资源与独立验收

Cesium 沿用官方框架模板与逐应用增强；按官方四类资源目录部署，固定版本并验证静态复制插件新版路径语义。选择本地椭球/标记点，关闭默认在线数据服务，避免模板要求账户或 Token。配置增量插入并备份，首页构建入口保留，专项双入口验证另行执行。Cesium 的模型加密尚未接入，不把 Three 的密钥脚本直接生成到 Cesium；多引擎暂不同时安装。

## 2026-10-28：Babylon ES 模块与逐应用隔离

Babylon 首期采用固定版本 @babylonjs/core 的 ES 深路径模块，按需创建本地最小场景；不引入 CDN、模型加载器、额外静态资源插件或无作用的加密脚本。保留官方首页、入口与 Vite 配置，以独立验收页验证模块分块与生命周期。按应用单选语义保留；多引擎选项及模型适配另行设计，不将最小场景称为完整多引擎或模型支持。

2026-10-29：多选采用规范顺序复用现有单引擎阶段，保持官方模板、旧参数与独立验收页；模型保护限定 Three，不引入同页多引擎运行时。

2026-10-29：联合构建实测 Babylon 动态加载会牵连 Cesium 分块，选择显式引擎分组且禁用递归捕获依赖、保持严格执行顺序；仅修改专项构建工具，普通生成配置保留。依据 [Rolldown 官方说明](https://rolldown.rs/in-depth/manual-code-splitting)。

## 2026-10-29：Babylon 模型与共享校验

采用与 core 同版的 @babylonjs/loaders 9.32.1，动态导入 glTF 并用官方 LoadAssetContainerAsync 接收内存字节。授权解密、GLB 格式检查和引擎容器生命周期分离；共享校验移入 model-security，Three 的公开导出不变。只接受自包含 GLB，避免隐式远端资源及解码器下载。加载器可能保留原字节视图，因此提交独立副本，仅清零临时解密缓冲。先验收本地 GLB/.adui，env 自动构建另行接入，避免把未验证的保护选项开放给 Babylon。依据 [Babylon 官方加载文档](https://github.com/BabylonJS/Documentation/blob/master/content/features/featuresDeepDive/importers/loadingFileTypes.md)。

2026-10-29 后续：Babylon 自动构建复用已有 env 插件、密钥工具与同源限长下载，增加引擎适配参数，保持加密核心独立。多引擎只安装一套模型插件与 KEY，优先 Three 保持已有行为；没有 Three 时选择 Babylon。旧快照拒绝覆盖升级，避免自动修改既有引擎源码。客户端拆分只是提高直接复用成本，不能称为无法提取。

## 2026-10-29：Cesium 模型就绪与 Blob 生命周期

Cesium 使用公开 Model.fromGltfAsync({url}) 接收受控 Blob URL，复用共享授权/GLB 核心。按固定版本实现，创建结果仍须加入场景处理资源，因此使用隐藏候选、readyEvent/errorEvent、限时请求帧完成就绪判断，再替换旧模型；取消/失败回收候选、监听与 URL。Blob 的明文副本随资产持有，不能宣称清零全部内存。先完成本地文件与授权适配，再单独验收 env 自动构建。依据 [官方 Model 文档](https://cesium.com/learn/cesiumjs/ref-doc/Model.html)。

2026-10-29 后续：Cesium 接入原 env 构建插件、密钥脚本与同源限长下载，不引入第二套密码格式。模型适配优先级固定为 Three → Babylon → Cesium，以保留既有组合入口；多引擎只安装一套 KEY/插件/模型页。默认 loader 在场景导入前设置资源 base，模型应用验收同步检查四类 Cesium 资源。关闭保护及旧快照拒绝覆盖的行为保持明确。

## 2026-10-29：引擎绘图比例和 DPR 无事件兜底

Cesium/Babylon 采用与现有 Three 相同的最高 2 倍 DPR、最长边 8192 策略；Babylon 再限制硬件最大纹理尺寸。使用引擎公开 API，维持引擎层 CSS 像素与 HUD 设计像素分离。Chrome 实测 DPR 仿真可能不发送 resize/媒体查询事件，因此保留事件监听并增加逐帧标量检查；仅变化时触发尺寸刷新，卸载取消待执行帧。共享模块按引擎复制而非要求升级旧 adui-screen 源码；继续执行已有文件拒绝覆盖策略。原生全屏拒绝与工具中止如实记录为待验收。

## 2026-10-30：默认基础样式采用本地静态快照

按用户指定的 normalize.css URL 保存 8.0.1 固定快照与 MIT 许可，在 Vite+ 官方生成完成后增量加入应用入口。不引入 normalize.css npm 包或创建/运行时远程下载，不替代官方 Vue/React 模板。先执行可选 UI/CSS，再将基础样式整理到前面；同名未知文件及修改过的快照拒绝覆盖。版本、原始/格式化 SHA256 见 [来源记录](../../packages/create/assets/normalize.SOURCE.md)。
